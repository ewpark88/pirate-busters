# 퀄리티 진단 → 개선 단계 제안 계획

## Context
사용자가 게임의 전체 퀄리티(그래픽·아트, 전투 손맛·연출, UI·메뉴, 게임성)에 크게 실망했다. 기준은 **"적어도 캐슬버스터즈 정도는 돼야 사용자를 모을 수 있다"**이다. 사용자는 **진단을 먼저** 하는 방향을 골랐다.

지금 무엇이 얼마나 부족한지 실제 화면으로 확인한다. 그 결과로 우선순위가 붙은 개선 단계(A<n>)를 계획서에 제안한다. 이번 계획에서는 코드를 고치지 않는다.

## 사전 조사로 이미 보이는 약점
- **메타 UI가 가장 약하다.** 테마 색만 바꾼 Material 기본 위젯을 그대로 쓴다(FilledButton 12, ListTile 10, Chip 10, AppBar 7, `Icons.*` 약 50곳).
  - 받아 둔 `app/assets/ui/kit/` 버튼·패널·탭·칩·배지 8장을 코드가 한 번도 쓰지 않는다.
  - 화면 전환은 8곳 모두 `MaterialPageRoute`이고, 메타 화면에 애니메이션이 거의 없다.
  - 조선소(`app/lib/shipyard/shipyard_screen.dart`)가 특히 "툴 화면" 느낌이다.
- **사운드에 음원 파일이 0개다.** 효과음 9종과 배경음악 2곡을 모두 `PcmSynth`로 코드 합성한다(`app/lib/audio/`). 칩튠 느낌이 강하다.
- **카메라:** A14(탄 추적)를 아직 시작하지 않았다. 지금은 넓게 줌아웃해서 긴장감이 약하다.
- **흔들림:** 짝·홀 사각파로 흔들려 딱딱하다(`app/lib/game/fx_layer.dart`).
- **크기:** 전투 해적이 약 22×29px로 아주 작다.
- **바다 질감:** 파도 진폭 ±2px, 단색 원 포말로 단순하다.
- **실기기 손맛 체크포인트:** M4부터 계속 이월되어, 사람이 직접 느껴 본 검증이 없다.

## 진행 단계

### 1. 실제 화면 캡처 (읽기·실행만)
- `run` 스킬로 앱을 실행한다. 이 장면들을 캡처한다:
  - 항구
  - 조선소
  - 선원
  - 캠페인 지도
  - 전투 준비
  - 전투: 조준, 발사, 탄 비행, 착탄, 침수, 격침
  - 결과
  - 설정
- 캡처는 저장소 밖 scratchpad에 두고, 문서로 남길 몇 장만 `docs/quality/img/`에 옮긴다.

### 2. 캐슬버스터즈 기준 정리
- 스토어 소개와 공개 리뷰를 WebSearch로 조사해, 기준 게임의 핵심 요소를 정리한다:
  - 화면 구성
  - 타격 연출
  - UI 스타일
  - 성장·보상 루프
  - 사운드
- 저작권이 있는 이미지는 저장소에 넣지 않는다. 사용자가 비교용 스크린샷을 주면 함께 대조한다.

### 3. 격차 진단 문서 작성
- 위치: `docs/quality/2026-10-02-gap-analysis.md` (색인 `docs/plans/README.md`에 한 줄 추가)
- 4개 축(아트, 손맛·연출, UI, 게임성)마다 이것을 적는다:
  - 현재 상태 (캡처와 파일 경로)
  - 기준과의 차이
  - 영향도(상·중·하)
  - 비용(0원 원칙 안에서 가능한지)
- **게임성 쪽:** 규칙·수치 변경이 필요하면 설계서·BALANCE.md를 직접 고치지 않는다. 수정 제안 목록으로만 적는다(절대 규칙 12).

### 4. 개선 단계 제안 (사용자 승인 후 계획서 반영)
초안은 진단 결과로 확정한다. 계획서 12장 끝에 A15부터 붙인다(절대 규칙 11). 순서는 영향이 큰 것부터 둔다.

| 단계 | 내용 | 주요 파일 |
|---|---|---|
| A14 (기존) | 탄 비행 1.3배, 탄 추적 카메라. 먼저 끝낸다 | `app/lib/game/camera_director.dart` |
| A15 (다른 세션 진행 중) | 에셋 v0.26 피해 표현 v3. 내 단계는 그 뒤 번호를 쓴다 | `damage_painter` 등, `battle_cues.dart` |
| A16 메타 UI 리스킨 | `ui/kit` PNG로 공용 위젯 `PbButton`·`PbPanel`·`PbTab`·`PbChip`을 만든다. Material 위젯과 `Icons.*`를 메타 아이콘으로 바꾼다. 커스텀 화면 전환(`pageTransitionsTheme`)과 등장 애니메이션을 넣는다. 조선소부터 시작한다 | `app/lib/app/app_theme.dart`, `shipyard/`, `port/`, `campaign/`, `crew/`, `ui/hud/result_overlay.dart` |
| A17 전투 손맛 2차 | 감쇠 노이즈 흔들림, 발사 반동, 피격 배 출렁임, 격침 슬로모, 큰 피해 숫자, 결과 화면 연출. **A15가 머지된 뒤에 착수한다** (`battle_cues.dart`가 겹침) | `fx_layer.dart`, `battle_cues.dart`, `ship_motion.dart` |
| A18 사운드 교체 | CC0 샘플 효과음(Kenney, OpenGameArt CC0 등)과 CC0 배경음악. 합성음은 대체 수단으로 남긴다 | `app/lib/audio/` |
| A19 아트 보강 | 해적 전투 크기와 시인성, 바다 파도 진폭과 포말 질감, 미사용 에셋 정리. `docs/ASSETS.md`는 A15 머지 뒤에 고친다 | `sea_view.dart`, `sprites.dart`, `docs/ASSETS.md` |
| 번호 | 계획서에 반영할 때 그 시점의 12장 마지막 번호를 다시 확인한다 | |
| (제안만) 게임성 | 설계서·BALANCE.md 수정 제안 목록. 사용자가 결정한다 | 설계서, BALANCE.md |

- 승인되면 `/doc-sync` 규칙에 따라 계획서와 해시를 맞춘다. 계획 변경은 `/adr`로 ADR을 남긴다.

## 주의
- 이 작업 트리는 다른 세션과 공유한다. 지금 브랜치는 `feat/A13-battle-fx`이고 커밋 안 된 파일(`.claude/settings.json`, `CLAUDE.md`, `docs/plans/frolicking-launching-spindle.md`)은 내 것이 아니라 건드리지 않는다. git add는 내 경로만 한다.
- 이 계획 파일은 실행할 때 `docs/plans/2026-10-02-quality-diagnosis.md`로 옮기고 원본은 지운다.

## 검증
- 진단 문서에 4개 축 모두 캡처 근거, 기준 대비 차이, 우선순위가 들어 있는지 확인한다.
- 계획서를 반영했다면 `dart run tool/check_doc_sync.dart`로 검사한다. 문서만 바뀌므로 이 검사로 끝낸다.
- 커밋은 사용자가 요청할 때만 한다.
