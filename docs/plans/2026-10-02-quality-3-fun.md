# 퀄리티 3차: "하고 싶게 만드는" 재미 — 배 키우기·배 모양·보스·감정 연출·첫 10분

## Context
사용자 요청: "퀄리티를 끊임없이 올려라. 복잡하게 말고, 사용자가 재미있어서 하고 싶게."
앞선 진단(A14~A24)은 메타 UI·탄·HUD·음원·흔들림·판 길이를 고쳤다. 이번 조사(골든·코드·문서)에서 남은 "재미" 구멍은 이렇다.
- **배가 예쁘지 않다(사용자 지적).** 사각 블록을 벽돌처럼 쌓은 직사각형이다. 블록마다 테두리가 있어 판자가 이어지지 않는다. 처음부터 12×8 슬루프가 꽉 찬 "완성된 배"로 시작해서, 배를 키워 가는 재미가 없다.
- **보스가 가짜다.** 1-5·1-12 의 기믹(`bow_iron_shield`·`patrol_closing_in`)은 전투 준비 화면의 글자로만 있고, 판정은 일반전과 같다.
- **감정이 터지는 순간이 없다.** 격침·큰 한 방 슬로모션, "대박/연속 명중" 문구, 전투 중 해적 한마디·상대 도발, 해적 추락·KO 소리가 없다.
- **첫 10분이 허술하다.** 튜토리얼은 HUD 힌트 한 줄뿐이다. 항구에 "다음에 할 일"이 없다. 전투 준비의 상대 패널은 한 줄 대사 아래가 비어 있다.
- **사람이 해 본 적이 없다.** 손맛 20판은 M4부터 이월됐다.

사용자 결정:
- 넣을 것(추가 요청 포함): 돛대 칸·돛 자리(피해 +20%, 잘 부러짐, 돛대 종류 5개, 골드로 돛대 내구도 업그레이드), 배 업그레이드 전부 골드(확장 단계·선형 레벨·재질·모듈), 슬루프 단계 테스트용 선택·열림 간격 확대, 감정 연출, 보스 기믹, 첫 10분, 에이전트 직접 플레이 점검, 돛단배 → 칸 늘리기, 배 모양(그림 + 선체 모양 격자 둘 다).
- 계획 순서(R1d → R2 → R3 → R4)는 유지한다. 새 작업은 **R1d 뒤**에 한다. 성장·상자·미션은 R4 그대로 둔다.

### A27 돛대 칸·돛 자리 (사용자 추가 요청) — `pb_sim`, `pb_data`, `pb_ai`, `app`
- 지금은 돛대·돛 그림이 격자 밖 장식이라 맞지도, 부서지지도 않는다. 이것을 바꾼다.
- `pb_sim`
  - 돛대 종류 5개(대나무·소나무·참나무·철·망대)를 데이터로 둔다. 칸 수 2~4, 내구도, 무게, 건조 포인트, 돛 자리 피해 15~30%, 특성(대나무 연료 벌칙 절반, 소나무 불에 약함, 철 불 면역)이 다르다. 수치는 수정안 A3.2 아래 표.
  - 돛대 모듈이 종류에 맞게 돛대 칸을 세운다(격자 위끝까지).
  - 돛대 칸 하나가 부서지면 돛대가 부러진다. 위 칸은 무너지고, 지금 있는 `_breakMast` 연료 2배·속도 반을 그대로 쓴다.
  - 돛 자리: 돛대 꼭대기 칸에 해적 1명(선실 슬롯 하나로 센다), 피해는 종류별 보너스.
  - 돛대가 부러지면 돛 자리 해적은 바다로 떨어진다. 다음 턴에는 돛대 밑동 칸으로 드러난 채 돌아온다.
  - 돛대 레벨(내구도)을 매치 시작 때 정수로 받는다. 선체 보정과 같은 방식이다.
  - 시드 고정 해시 테스트를 넣고, 골든을 다시 만든다.
- `pb_data`·`pb_ai`
  - 스테이지 JSON 에 적 돛대 레벨을 넣는다.
  - 설계도 JSON 에 돛 자리를 넣고, 추천 설계도 1종에 돛 자리를 둔다.
  - AI 는 상대 돛대·돛 자리 해적을 노리는 점수를 쓰고, 제 배 돛 자리에도 해적을 태운다.
- `app`
  - 돛·돛대 그림(`module_painter.dart`)을 돛대 칸에 붙여 칸 손상 단계별로 찢어지고, 부러지면 넘어져 바다로 떨어지게 한다(`collapse_fx.dart`).
  - 돛 자리 해적을 그린다. 조선소에서 해적을 돛 자리로 끌어다 놓는다.
  - 돛대 종류마다 돛·돛대 그림을 다르게 한다. 대나무 마디, 철 띠, 망대 꼭대기 바구니. 새 그림은 A24 요청서에 더하고, 오기 전에는 코드 그리기로 한다.
  - 조선소 팔레트에 돛대 종류를 넣고, 잠긴 종류에는 자물쇠와 금액을 보여 준다.
  - 돛대 업그레이드: 조선소에서 골드로 종류마다 Lv1~5 를 올린다(레벨당 내구도 +10). 진행 저장에 넣는다. 개발 도구가 켜져 있으면 레벨을 마음대로 고른다. 글자는 ko·en.
- 테스트
  - 소나무 돛대 Lv1 은 한 발에 부러진다.
  - 종류별 돛 자리 피해(15·20·30%).
  - 부러지면 해적이 떨어지고 밑동으로 돌아온다.
  - 돛대 레벨별 내구도, 업그레이드 골드 차감·저장.
  - 돛대 종류별 칸 수·내구도·무게·특성, 종류 해금.

### A28 돛단배에서 키우기와 배 업그레이드 골드 — `pb_sim`, `pb_data`, `app`
- `pb_sim`: 선형 + 확장 단계로 격자 크기·틀·선실·포인트·모듈 한도를 정한다. 설계도 JSON 에 단계를 넣는다. 해시를 반영하고, 리플레이 버전을 올린다.
- `pb_data`·스테이지: 적 배도 그 스테이지의 단계를 쓴다(초반 적이 작아 판이 짧다). 튜토리얼 t-1 은 선실 2칸(옥토·톡).
- `app`
  - 저장된 설계도는 단계가 오르면 용골 기준으로 그대로 두고 새 칸만 빈다.
  - 조선소에서 새 칸이 빛나게 하고 안내를 띄운다. 추천 설계도는 새 단계 크기로 바꿔 준다.
  - 결과·항구에 '배가 커졌다!' 연출(배가 늘어나는 애니메이션 + 새 칸·선실 수)을 넣는다.
  - 저장 이전: 기존 사용자는 진행도에 맞는 단계를 받는다.
- 배 업그레이드는 모두 골드(사용자 추가 요청, 수정안 §13.6·A13.6):
  - 확장 단계: 스테이지로 열리고, 골드(300·600·1,200)로 짓는다.
  - 선형 업그레이드: R4 에서 골드 부분만 앞당긴다. 레벨마다 A13.7 골드, 효과는 A13.6. 조각은 R4, 건조 시간은 A4 에 그대로 남는다. 계획서 R4 문구도 같이 고친다.
    - `pb_sim`: 선형 업그레이드 보정 ‰ 정수를 매치 시작 때 받는다(§3.5). 선원 전력 보정은 R4 에 둔다.
  - 재질 해금(망사·코르크·철판), 모듈 해금(목수 공방·포문·망루·연료통·화약고).
  - 조선소 팔레트에서 잠긴 재질·모듈에 자물쇠와 금액을 보여 주고, 누르면 확인 창이 뜬다. 업그레이드할 수 있으면 빨간 점을 붙인다.
  - 추천 설계도는 잠긴 재질을 쓰면 열린 재질로 바꿔 보여 준다.
  - 경제: 해역 1 을 깨는 동안 무엇을 살 수 있는지 재고, 보상·금액 조정안을 올린다.
- 열림: 2단계 1-4, 3단계 1-8(R3 전에는 1-5), 4단계 1-12. 사용자 요청으로 간격을 넓혔다. 적 배 단계는 BALANCE A3.1 안을 따른다.
- 테스트용 단계 고르기: 개발 도구 스위치(A23 `devToolsProvider`)가 켜져 있으면 조선소·테스트 대전에서 단계 1~4 를 마음대로 고른다. 꺼져 있으면 보이지 않는다.
- 검증: `sim_runner` 로 단계별 판 길이·승률을 재고, 초반 판 2~3분을 확인한다.
- 테스트: 단계 해금, 설계도 이전, 연출 건너뛰기. 글자는 ko·en ARB.

### A29 보스 기믹 (해역 1) — `pb_sim`, `pb_ai`, `app`
- 1-5 꽃게 부대장 순찰선: 뱃머리 철판 방패가 직사 피해 50% 를 줄인다(A5.4). 방패 블록을 부수면 효과가 끝난다.

### A30 전투 감정 연출 — `app` (렌더 전용, 리플레이 해시 불변)
- 슬로모션: 격침·선실 직격·돛대 붕괴 때 렌더 재생 속도를 잠깐 0.3배로 한다. 시뮬은 틱 단위라 앱 쪽 재생만 늦춘다. 턴 타이머는 비행 중 이미 멈춰 있다.
