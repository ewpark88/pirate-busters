# 에셋 v0.26 피해 표현 v3 적용 (A15)


## 배경
디자인 쪽이 v0.26 패치(`D:\Projects\이미지참고용\pb_v0.26_patch`, 비교 페이지 38단계)를 보냈다. 폭탄 맞은 자리를 나무 배가 실제로 부서지는 모양으로 다시 그렸다: 부서진 칸에 배 속(어두운 벽·들보, 흘수선 아래는 물 찬 청록), 판자 3장이 다르게 부러지는 찢긴 가장자리, 결 따라 가는 쐐기 금, 판자가 뜯긴 구멍·꽃잎처럼 젖혀진 철판, 덩어리 단위 그을음과 불씨, 파편. 판정·데이터는 그대로이고 모양은 (칸 x, y, 번호) 해시 고정이라 리플레이가 같다.

바꿀 코드는 이미 끝난 A10(ADR-052 찢긴 가장자리)·A13(그을음) 코드다 → 절대 규칙 11 에 따라 계획서 12장 끝에 **A15** 로 넣는다.

## 문서 (먼저, 같은 커밋)
- `art/pb_v0.26_patch/` 로 패치 복사(v0.25 와 같은 방식). docs/ASSETS.md 에 v0.26 절. 예시 PNG(`png/fx/damage_v3`)는 앱에 넣지 않는다(코드로 그림 — `deferredImages` 또는 가져오기 대상 밖).
- ADR-070 “에셋 v0.26 수용: 피해 표현 v3, A15 신설”.
- 계획서 12장에 A15 (선행 A13, `app`): 항목 = 배 속·찢긴 판자·금·구멍·그을음·파편·저사양/캐시·골든. 완료 조건 = 리플레이 해시 불변, 1~4발 모습이 38단계 비교 캡처와 맞음, 프레임 유지, verify.
- 결정(사용자): A15 로 넣고 A14 보다 먼저 지금 진행. 설계서 문구 추가 승인.
- 설계서 §10.2 문구 추가(승인됨, 다른 세션에 해시 변경 알린 뒤): “부서진 칸에는 배 속(안쪽 벽·들보, 흘수선 아래는 물 찬 안쪽)이 보이고 부서진 칸 아래 블록 윗면에 판자 조각이 얹힌다.” §10.4 그을음: “맞은 자리(구멍·파괴 칸 덩어리) 가운데에서 번지고 불씨가 남으며 배 밖으로는 번지지 않는다.” 승인되면 `/doc-sync` 로 계획서 해시 갱신.

## 코드 (`app/lib/game/view/`, 각 300줄 이하)
참고 구현 `tools/py/damage38.py` 의 함수를 Canvas 호출로 1:1 옮긴다. 좌표는 32px 단위 칸 기준으로 만들고 `canvas.scale(cell/32)` 로 맞춘다. 앱 y 는 위로 증가하므로 Python 의 `t`(위) = 앱 `y+1`, `b` = `y-1` (`TornEdgePainter.up/down` 과 같음).

| 파일 | 내용 |
|---|---|
| `damage_style.dart` (새) | `damage_v3.json` 색 상수(oak·bot·pine·iron·interior·wet), `rnd(c,r,k)` 해시(Python 과 같은 비트 연산, 64비트 int 안에서 `& 0xffffffff`), `taper()` 쐐기 Path, 재질→팔레트(젖은 나무는 `bot`; 코르크는 pine, 망사는 oak 팔레트로 나무 규칙 — 패치에 없어 기본값으로 정함) |
| `damage_painter.dart` (교체) | `interior`(열린 변 그라데이션 / 꽉 채움 + 벽 3줄 + 들보 + 젖음 거품), `crackWood`·`crackIron`, `holeWood`·`holeIron` |
| `torn_edge_painter.dart` (교체) | `tornWood`(좌우 판자 3장 패임/튀어나옴, 위아래 5구간 톱니 + 가시), `tornIron`(말린 철판 + 주황 선), `debris`, 격자 순회 `mask` 는 유지 |
| `scorch_painter.dart` (교체) | 손상 2 이상 칸(구멍 + 설계도에 있던 파괴 칸)의 이어진 덩어리마다 중심·반경 `C*(1.3+0.25√n)`, 타원 5개 방사 그라데이션 + 불씨 7개, 블록·배 속 칸 합집합으로 `clipPath` |
| `damage_layer.dart` (새) | 위 순서(배 속 → 그을음 → 금 → 구멍 → 찢김 → 파편)를 `PictureRecorder` 로 한 장에 녹화, 키 = 칸별 단계 + 젖은 줄 경계. 키가 바뀔 때만 다시 그림(매 프레임 Path 수백 개 생성 방지) |

- `ship_view.dart`: 칸 루프는 타일·선실·모듈만 그리고, 루프 뒤에 `DamageLayer` 한 번. 기존 `DamagePainter.broken`·`TornEdgePainter.damage/tornAll`·`ScorchPainter.draw` 호출을 뺀다. 착탄 전 스냅샷(`shot.before`) 처리는 그대로.
- 그을음이 손상 상태에서 정해지므로 `ShipView.scorched` 집합과 `battle_cues.dart` 의 `scorched.add` 2곳, 쓰이지 않게 되는 `ExplosionFx.scorch` 참조를 지운다(다른 사용처 있으면 유지).
- 바깥 윤곽선(Python `outline`)은 지금 타일 그림에 있으므로 그리지 않는다.

## 테스트
- `app/test/damage_v3_test.dart`(새, 한국어 이름):
  - `rnd` 가 Python 참고 구현 값과 같다(몇 개 (c,r,k) 값을 `py` 로 미리 계산해 고정).
  - 색 상수가 `art/pb_v0.26_patch/fx/damage_v3/damage_v3.json` 과 같다.
  - 같은 격자·단계면 녹화 결과가 같고(이미지 바이트 비교), 키가 안 바뀌면 다시 녹화하지 않는다.
  - 그을음 덩어리: 이어진 구멍·파괴 칸이 한 덩어리, 떨어진 칸은 두 덩어리.
- 골든 `damage_{h0..h3}.png`(작은 배에 1~4발 누적, 고·저사양 같음)를 새로 만들고 `reference/screens_v2/stage38_h0~h3.png` 와 눈으로 대조.
- 기존 골든 중 손상된 배가 나오는 것은 다시 만든다. 리플레이·해시 테스트는 바뀌지 않아야 한다.
