## 문서 구성 (작성할 내용)

**머리말**: 제목, 날짜(2026-09-29), 기준 문서 링크(`Pirate Busters 게임 설계서.md`).

**1. 개요**
- 목표: MVP로 '당겨 쏴서 배를 부수는 손맛'을 검증하고, KPI를 통과하면 단계별로 확장한다.
- 개발 원칙 요약: 결정론 + 커맨드 구조를 처음부터 적용, 0원 원칙, mozzi 스택 재사용, AI 대전 먼저.
- 전체 단계 요약표: Phase 0 준비 → MVP(M1~M7, 6주) → 비공개 테스트(2주) → 정식 출시(약 4개월) → 비동기 PvP → 실시간 PvP → 운영. 각 단계에 기간, 진입 조건, 산출물을 적는다.

**2. 개발 기반 (공통 규칙)**
- 모노레포 구조(§7.3): `packages/pb_sim`, `pb_ai`, `pb_data`, `pb_net`(나중에), `app/lib/{render,input,shipyard,meta}`, `tools/sim_runner`. 패키지 의존 방향: `pb_sim` ← `pb_ai`, `pb_data` ← `app`. `pb_sim`은 Flutter에 의존하지 않는다.
- 결정론 코딩 규칙(§7.1)을 체크리스트로 정리: 30Hz 고정 틱, ×1000 고정소수점, 정수 삼각함수 테이블, xorshift32, id 순서로 갱신, 물리 엔진은 연출에만 사용. `pb_sim` 안에서 `double`, `dart:math`, `Random()`, `DateTime`을 쓰지 못하게 하는 린트 규칙과 import 검사 스크립트도 둔다.
- 테스트 전략: `pb_sim`/`pb_ai` 유닛 테스트, 골든 리플레이 해시 테스트(100개), `sim_runner` 밸런스 회귀 테스트, 실기기 2대 해시 비교.
- CI: GitHub Actions 무료 한도 안에서 lint, test, 해시 테스트를 돌린다.
- 완료 정의(DoD): 테스트 통과, 해시 불변, 린트 통과, 관련 설계서 항목에 체크.

**3. Phase 0 — 준비 (2~3일)**
- 저장소와 git 초기화, melos 워크스페이스, 패키지 스캐폴딩, CI 뼈대
- mozzi에서 재사용할 모듈 목록 만들기: 당기기 입력, 게이지, 2.5D 렌더 규칙, Firebase, AdMob, IAP 래퍼, `stage_table` 구조
- 상표 사전 검색(KIPRIS, USPTO, §12). 결과는 출시 전 게이트에 반영한다.
- 미정 사항 결정: 로컬 DB(Isar 또는 Hive), 대상 플랫폼(Android 우선 여부)

**4. MVP 상세 (6주)**: 마일스톤마다 목표, 태스크 체크리스트, 완료 조건, 설계서 참조를 적는다.
- **M1 (1주차) 시뮬레이션 코어**: 고정소수점 타입, 정수 sin/cos 테이블, xorshift32, 틱 루프, `Command`(FIRE/TAP/SURRENDER), 매치 상태, 상태 해시, 리플레이 포맷(시드 + 설계도 + 덱 + 커맨드), 격자 배 데이터 구조, 블록 재질 5종.
  완료 조건: 같은 입력에서 해시가 같고, 리플레이 직렬화 왕복이 통과한다.
- **M2 (2주차) 탄도·타격·붕괴**: 포물선 탄도와 바람, 격자 충돌(DDA), 블록 피해와 손상 단계, 용골 연결 BFS와 떨어진 덩어리 붕괴, 해적 엔티티(HP, 선실 슬롯, 재장전 쿨타임), 선실 파괴 시 피해와 바다 낙하, 헤엄 복귀(4초), 교대 대기열, 승리 조건 중 전멸과 파괴.
- **M3 (2~3주차) 파도·침수·기울기**: 정수 사인파 흔들림, 흘수선 계산, 침수율과 가속 복리, 기울기와 발사각 보정, 침몰 승리, 3분 판정, 폭풍 타임(마지막 30초).
  완료 조건: 헤드리스 매치 한 판이 끝까지 돌아가고 결과가 결정론적이다.
- **M4 (3주차) 렌더·입력 → 첫 플레이어블**: Flame 전장, 틱 사이 보간, 블록 손상 3단계 코드 렌더, 바다 사인파와 포말, 해적 파츠 렌더(최소 세트), 당겨서 쏘기 → FIRE 커맨드(mozzi 재사용), 궤적 앞 30%만 점선 표시, 카메라 팬과 핀치 줌, 파편과 물보라 파티클, 진동, 합성 효과음.
  **손맛 체크포인트**: 여기서 직접 플레이해 보고 문제가 있으면 조작부터 고친다.
- **M5 (4주차) 해적 12명·모듈·건조**: `pb_data` JSON 스키마와 검증, 행동 모듈(projectile, onHit, onTap, onLand) 중 MVP에 필요한 것부터 구현. 해적 12명: 버키, 플레임(투척) / 핀, 로지(직사) / 해리(관통) / 스키퍼(물수제비) / 버블(수중) / 폴리, 갈매기 폭격대(공중) / 브루노(강습) / 우디, 버킷(지원). 슬루프 선형, 기능 모듈 8종, 건조 포인트 상한, 간이 건조 화면, 추천 설계도 3종, 설계도 JSON 저장(3개).
- **M6 (5주차) AI·sim_runner**: 조준 솔버(후보 샘플링 12×8, 착탄 점수화, 프레임당 8개로 분할 계산), 난이도 3단계(쉬움, 보통, 어려움), 성격 4종의 가중치 표, 연패 보정, `AiController`. `sim_runner` CLI로 AI 대 AI 대량 시뮬레이션과 승률 리포트.
- **M7 (6주차) 캠페인·메타 최소·출시 준비**: 해역 1(5스테이지와 보스 해군 초계선 기믹), 스테이지 JSON과 Remote Config, 별 3개 판정, 로컬 저장, Firebase(Analytics 이벤트 정의, Remote Config, Crashlytics), AdMob 승리 보상 2배, IAP 광고 제거, 첫 3판은 건조 없이 진행, 저사양 모드 스위치, 실기기 2대 해시 검증, 비공개 테스트 빌드.
- MVP 종료 게이트: 설계서 §11.1 체크리스트와 결정론 CI를 모두 통과해야 한다.

**5. 비공개 테스트 (2주)**: Play 비공개 테스트(12명 × 14일), KPI 이벤트 수집, §11.3 기준표, 기준에 못 미칠 때 고칠 순서(조준 손맛, 타격감, 붕괴 연출).

**6. 정식 출시 (약 4개월, 개략)**: 마일스톤 R1~R6
- R1: 해적 40명과 행동 모듈 약 20개
- R2: 선형 4종과 유령선
- R3: 해역 2~6과 보스 기믹, 지옥 난이도
- R4: 메타(항해 랭크와 티어, 오늘의 해전, 성장과 특성, 재화, 보물상자)
- R5: 상점과 수익화 전체(§9), PGS 로그인·리더보드·클라우드 세이브, 확률 표기
- R6: 폴리싱과 출시 체크리스트(상표, 스토어 등록)
각 마일스톤에는 주요 산출물과 완료 조건만 적는다.

**7. 2단계 비동기 PvP '유령 함대'**: 진입 조건 DAU 1,000 이상. Workers + KV/D1 업로드·매칭 API, `pb_net`, 설계도 업로드와 검증.

**8. 3단계 실시간 PvP**: 진입 조건 동시 접속 피크 100명 이상. Durable Objects 중계, 롤백 넷코드와 스냅샷, 5초 해시 비교, 친구 대전부터 열고 랭크 매칭은 나중에, 20초 안에 매칭이 안 되면 유령 함대로 대체, 사용량 알림.

**9. 운영**: 월간 시즌 루틴(해적 4명과 스킨 추가), 주 1회 `sim_runner` 밸런스 점검.

**10. 리스크 추적**: 설계서 §12의 리스크마다 대응이 들어가는 마일스톤을 연결한 표.

**11. 미정 사항**: 로컬 DB, 대상 플랫폼, mozzi 코드 가져오는 방식(복사할지 공용 패키지로 둘지), CI 저장소 공개 여부.
