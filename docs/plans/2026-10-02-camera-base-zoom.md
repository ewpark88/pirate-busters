# 전투 기본 화면 확대 (카메라 baseWidth 축소)

## Context
전장이 넓어 보여 답답하다는 판단으로 “전장 축소”를 검토했다. 실제 거리(간격 2~42칸)를 줄이면 사거리·밸런스·설계서·BALANCE·골든·sim_runner 재측정까지 연쇄되므로, 사용자는 **화면만, 그중 기본 화면을 더 확대**하는 쪽을 골랐다.
최대 줌아웃(간격 42칸 전부 보기, `maxWidth` 2528)은 그대로 두므로 설계서 §2.1 문구와 어긋나지 않는다 → 설계서·BALANCE·계획서 수정 없음, 렌더 전용 변경.

## 현재 값 (`app/lib/game/camera_director.dart`)
- `baseWidth = 900` (약 28칸, 1칸 32px `app/lib/game/coords.dart`)
- `minWidth = baseWidth / 1.5` (핀치 최대 확대, 자동으로 따라감)
- 기본 화면 중심: 내 배 + `ahead 260`(조준 시 +300), y = −120
- `baseWidth` 는 탄 추적·전체 보기 폭의 **하한**(`clamp(baseWidth, maxWidth)`)으로도 쓰인다

## 제약: 배가 화면에 들어와야 한다
- 화면 세로 = 폭 × aspect(가로 화면 약 0.46). 900 → 세로 414px, 720 → 331px.
- 가장 큰 갤리온 18×11칸 = 576×352px. 720 이면 가로 반폭 360 인데 배 중심이 화면 중심에서 260 뒤라 **선미가 잘리고**, 세로도 돛대 끝이 잘릴 수 있다.
- 그래서 폭만 바꾸지 말고 `ahead`(앞바다 비중)와 중심 y 를 같이 비례 조정해야 한다.

## 변경
1. `camera_director.dart`
   - `baseWidth` 900 → **약 760** (720 은 갤리온이 잘릴 가능성이 커서 실측 뒤 결정. 값은 상수 하나라 실기기에서 조정 쉬움). 주석 “약 28칸” 갱신.
   - `ahead` 260 → `baseWidth` 비례(예: `baseWidth * 0.29`)로 바꿔 내 배가 화면 안에 남게.
   - 중심 y(−120)는 갤리온 돛대 끝이 들어오는지 확인 후 필요 시 조정.
   - 탄 추적 하한이 같이 낮아지는 것은 그대로 둔다(탄 추적은 보통 `+500`·높이 기준이 더 커서 영향 적음).
2. `app/test/render_test.dart` — 상수 참조라 대부분 그대로 통과. **새 테스트 추가:** “기본 화면에 갤리온(18×11칸) 내 배가 가로·세로 모두 들어온다” (aspect 0.46 기준).
3. 문서: `docs/DECISIONS.md` 에 짧은 ADR(기본 화면 확대, 렌더 전용, 실측값), `CHANGELOG.md [Unreleased]` 한 줄. `docs/ASSETS.md`/tokens.json 에 baseWidth 가 없음을 확인했으므로 에셋 문서는 그대로.

## 범위·순서 메모
- 지금 브랜치 `feat/A15-damage-v3` 에 커밋 안 된 A15 작업이 있다. 이 변경은 렌더 상수 하나라 단계 범위(절대 규칙 1·11) 판단이 필요: 손맛 조정으로 보고 현재 단계에 끼울지, 계획서 12장 끝 `A<n>` 으로 둘지 착수 전 사용자 확인.
- 설계서·BALANCE·pb_sim 변경 없음 → 골든·sim_runner 영향 없음.

## 결과 (2026-10-02)
- 계획서 A22, ADR-072 로 두었다(사용자 결정).
- 실측 계산: 폭 900·앞바다 260 에서도 브리건틴 이상은 선미가 잘렸다(갤리온 98px). 그래서 `idleAhead = baseWidth/2 − 7칸 − 16` = 140 으로 브리건틴 전체가 들어오게 했다. 가운데 높이는 −120 → `idleY` −150 으로 바꿔 화면 위 끝이 폭 900 때(−327)와 같다(−325). 수면 아래는 25px 보인다.
- 갤리온은 여전히 선미가 조금 잘린다(기본 화면은 “내 배와 앞바다”). 실기기에서 본다.
