# M1 — 시뮬레이션 코어 (`pb_sim`) 구현 계획

## Context
Phase 0 완료(docs/PROGRESS.md). 개발 계획서 순서상 다음은 **M1: 결정론의 바닥**. 이후 모든 전투 코드(M2 탄도, M3 침수…)가 이 위에서 짜인다.
완료 조건: 같은 시드·커맨드로 1,000틱 → 해시가 매번 같음. 리플레이 저장 후 다시 읽어도 결과 같음.
현재 git: main 에 커밋 없음, 전부 미추적. 사용자 지시: 원격 `https://github.com/ewpark88/pirate-busters.git` 에 커밋.

## 0. Git 준비
1. `bash tool/verify.sh` 로 Phase 0 상태 통과 확인.

## 1. 구현 (packages/pb_sim/lib/src/…, 파일당 ≤300줄, 공개 API는 `pb_sim.dart` 에서 export)
| 파일 | 내용 (설계서 참조) |
|---|---|
| `math/fx.dart` | `extension type Fx(int raw)` ×1000. `+ - * ~/`, `mul`/`div` 반올림 = 0에서 먼 쪽 half-up, 범위(±2^40) 초과 시 `StateError` (계획서 §2.2) |
| `math/int_math.dart` | `isqrt`(정수 뉴턴법), `atan2Mdeg(y, x)` → 밀리도 (테이블 이분 탐색) |
| `math/trig.dart` + `math/trig_table.dart` | 0~90° 0.25° 간격 361개, 값 ×1,000,000. `sinMdeg`/`cosMdeg`(밀리도 입력, 사분면 대칭 + 선형 보간), Fx(×1000) 반환 버전 |
| `random/xorshift32.dart` | mozzi `seeded_rng.dart` 복사 후 수정(첫 줄 `mozzi …` 주석): double 제거, `nextInt(max)=(x*max)>>32`, `nextRange(lo,hi)`, `state` 게터(해시용) |
| `ship/material.dart` | 재질 5종 enum: 내구도·무게(×1000, 망사 500)·비용·특성 플래그(불 약함/불 면역/부력/감속) (§3.2) |
| `ship/hull.dart` | `HullSpec`(폭·높이·선실 슬롯·건조 포인트). MVP 는 슬루프 12×8/4/60 만 상수로 (§3.1) |
| `ship/blueprint.dart` | 설계도: 선형 + 셀 목록(x,y,재질). 비용 ≤ 건조 포인트, 격자 범위 검증. toJson/fromJson |
| `ship/ship_grid.dart` | 전투 중 격자: `List<int>` 재질 id·현재 내구도(행 우선 고정 순서) |
| `command/command.dart` | sealed `Command`: `FireCommand(tick, side, slot, angle, power)`, `TapCommand(tick, side, slot)`, `SurrenderCommand(tick, side)`. 정렬 키(tick→side→type→slot). toJson/fromJson (§7.2 형식 그대로) |
| `match/controller.dart` | `abstract interface class Controller { List<Command> commandsAt(int tick, MatchState view); }`, `ScriptedController` |
| `match/match_state.dart` | 틱 번호, rng, 양쪽 `ShipGrid`, 덱(해적 id 문자열 목록, 슬롯 수만큼 탑승), 슬롯별 재장전 잔여 틱, 결과(진행/항복승/시간 종료) |
| `match/match.dart` | `Match.start(seed, blueprints, decks)`, `step(commands)`: 커맨드 정렬 → 적용 → 재장전 감소 → tick++. M1 적용 범위: FIRE 는 슬롯·쿨다운 검증 후 기본 재장전(임시 상수 90틱=3초) 설정·rng 1회 소비(탄도는 M2), TAP 기록만, SURRENDER 는 종료. 3분(5400틱) 도달 시 종료 (§2.4) |
| `hash/state_hasher.dart` | FNV-1a 32 비트. 정해진 순서로 int 를 바이트 단위로 먹임. `hashState(MatchState)` |
| `replay/replay.dart` | 시드 + 양쪽 설계도 + 덱 + 커맨드 목록. toJson/fromJson(`Map<String, Object?>`), `Replay.run(ticks)` → 해시 |

`tool/gen_trig_table.dart`(워크스페이스 도구, dart:math 사용 가능)로 `trig_table.dart` 생성. 생성 파일 첫 줄에 생성기 표기.

## 2. 테스트 (packages/pb_sim/test/, 이름은 한국어 문장)
- fx: 반올림·음수·오버플로 예외
- trig: 모든 0.25° 지점에서 dart:math 대비 오차 ≤ 1(×1000), 사분면 대칭; isqrt 경계값; atan2 8방향·오차 ≤ 0.25°
- xorshift32: 시드 0 대체, 고정 시드 첫 5개 값 고정, nextInt 범위·분포 대략 균등
- blueprint/grid: 비용 초과·범위 밖 거부, JSON 왕복
- command: 정렬 순서, JSON 왕복(§7.2 예시 문자열 그대로 파싱)
- match: 쿨다운 중 FIRE 무시, 항복 시 종료, 5400틱 종료
- **반복 해시(필수)**: 같은 시드·스크립트로 1,000틱 × 여러 번 → 같은 해시; 시드 바뀌면 해시 바뀜; 고정 기대 해시값(골든) 1개
- **리플레이**: 저장 → jsonEncode → decode → 재실행 해시 동일
