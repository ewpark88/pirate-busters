# A63 선원 화면: 배 위 선실 배치·목록 필터·스크롤 중 잡힘 고침

## Context

사용자 요청(2026-10-13)은 세 가지다.
1. 왼쪽 출전 슬롯을 **건조한 내 배 그림**으로 보여 줘, 어느 해적이 어느 선실에 타는지 알 수 있게 한다.
2. 오른쪽 해적 목록에 **필터**를 넣는다: 등급별·계열별(사용자 확인: '케릭터별' = 계열)·탄종별. 레벨별은 해적 레벨이 생길 때(R4) 넣는다.
3. 해적이 많아져 목록을 손으로 스크롤하면 카드가 잡혀 끌려 나와 스크롤이 안 된다. 이것을 고친다.
4. (추가 요청) 해적을 **누르면 상세 보기**가 나와 정보와 설명을 볼 수 있다. **길게 누르면** 끌어서 선실에 배치한다.

조사 결과:
- **선원 화면 구조**
  - `app/lib/crew/crew_screen.dart` 는 왼쪽 `PbPanel`(폭 330)에 `CabinSlot` 카드(68×96)를 가로 한 줄로 늘어놓는다.
  - 오른쪽은 `GridView.extent` 에 `PirateTile` 을 그린다. 필터·정렬은 없다.
- **스크롤 중 잡힘 원인:** `crew_widgets.dart:246` `PirateTile` 이 즉시 끌리는 `Draggable` 이다. 손가락이 움직이는 순간 끌기가 GridView 세로 스크롤을 이긴다.
- **덱 순서와 선실의 관계:** 덱 순서 `deck[i]` 가 곧 설계도 `blueprint.cabins[i]` 칸이다(`match_state.dart:146`, `prep_cabins.dart:10`). 그래서 선실 칸 위치를 화면에 그대로 쓸 수 있다.
- **재사용할 것**
  - `myBlueprint(fleet, catalog, ship)`: `app/lib/meta/my_ship.dart`
  - `ShipGridView`: `app/lib/shipyard/ship_grid_view.dart`. 칸 좌표 식은 `Rect at(x,y) = (x*cell, (h-1-y)*cell)` 이다.
  - `BlueprintPreview`: 칸 크기 계산을 가져다 쓴다.
  - `RarityCard`, `ammoIconPath`/`ammoLabel`, 등급·계열 표시 글자
- **설계서 §13.7(1063행):**
  > 왼쪽은 배 옆모습과 선실 슬롯 … 오른쪽은 보유 해적 목록(계열·등급·세트 필터, 레벨·쿨다운 정렬) … 끌어다 놓으면 배치되고 자리가 바뀐다
  - 배 그림과 등급·계열 필터는 이미 설계서에 있다. 코드만 못 따라간 것이다.
  - **탄종 필터와 '길게 눌러 끌기'는 설계서에 없다.** 문장 추가가 필요하다.
- 계획서의 마지막 단계는 A61 이다. 이 작업은 끝난 M5·A9 화면을 다시 고치므로 **A62** 로 둔다(절대 규칙 11).

## 기준 문서 변경 (이 계획 승인 = 아래 문장 승인)

- **설계서 §13.7 편성 탭**
  - '계열·등급·세트 필터'를 '등급·계열·탄종·세트 필터'로 고친다.
  - 다음 문장을 덧붙인다:
    > 목록 카드는 길게 눌러야 끌려 나오고, 그냥 밀면 목록이 스크롤된다. 누르면 해적 상세(그림·등급·계열·코스트·체력·쉬는 턴·탄종·사거리·설명·이야기)가 뜬다. 해적보감(§13.9)이 생기기 전까지는 이 상세 창이 그 자리를 대신하고, 레벨업 버튼은 R4 에서 붙인다.
  - 왼쪽 문장에 덧붙인다:
    > 선실 칸 위에 탄 해적의 얼굴과 선실 번호를 겹쳐 그린다.
- **레벨 필터·정렬:** 계획서 R4(해적 레벨) 작업에 "선원 목록 레벨 필터·정렬"을 넣는다. 지금은 화면에 두지 않는다. 세트 필터는 A3(세트 효과) 몫으로 그대로 둔다.
- 계획서 12장 끝에 A62 절을 넣고, `기준 문서 동기화` 해시와 날짜를 고친다. ADR-109 를 남기고 STATUS·CHANGELOG·PROGRESS 도 고친다.
- 공유 트리 규칙(메모리 project-shared-worktree)을 따른다.
  - 착수·해시 수정 전에 다른 세션에 알린다.
  - checkout 하지 않는다. `git branch feat/A62-crew-ship-filter main` 만 만든다.
  - 커밋은 임시 인덱스와 `commit-tree` 로 main 위에 만든다.
  - verify 는 main + 내 변경만 담은 깨끗한 복사본에서 돌린다. 저장소 밖 D 드라이브 임시 폴더를 쓰고, 끝나면 지운다.

## 작업

### 1. 스크롤 중 잡힘 고침 (`crew_widgets.dart` `PirateTile`)
- `Draggable` 을 `LongPressDraggable` 로 바꾼다.
  - `delay` 는 약 200ms 이고, `hapticFeedbackOnStart` 를 켠다.
  - 끌려 나올 때 카드가 살짝 커지고 그림자가 생겨, 들어 올렸다는 것을 보여 준다.
- 탭은 빈 선실 자동 탑승에서 **상세 보기 열기**로 바꾼다(사용자 요청, 설계서 §13.7 "누르면 해적보감 상세"와도 맞다). 배치는 길게 눌러 끌기로만 한다. 상세 창에 '태우기' 버튼을 두어, 끌기가 어려운 사람도 빈 선실에 태울 수 있게 한다. 출전 중이면 '내리기'.
- 배 위 선실 배지는 스크롤 영역 밖이라 즉시 끌기를 유지한다. 선실끼리 자리를 바꿀 때 쓴다.

### 1b. 해적 상세 창 (새 `app/lib/crew/pirate_detail.dart`)
- `showPirateDetail(context, def)` 는 키트 스타일의 가운데 창(`PbPanel`)이다. 바깥을 누르거나 닫기 버튼으로 닫는다.
- 내용
  - 큰 `RarityCard`(등급 프레임), 이름
  - '등급 · 계열', 코스트, 체력, 쉬는 턴(쿨다운), 탄종 아이콘·`ammoLabel`, 사거리 등급
  - 설명(`pirate_<id>_desc`)과 이야기(`pirate_<id>_lore`). 둘 다 이미 ARB 에 있다.
- 버튼: '태우기'(빈 선실이 있고 코스트 안이면 켜짐) 또는 '내리기'(마지막 1명이면 꺼짐), 닫기.
- 새 글자 키(ko·en 같은 커밋): 상세 창 제목줄 항목 이름(코스트·체력·쉬는 턴·사거리), 태우기·내리기·닫기. 이미 있는 키가 있으면 다시 쓴다.
- 배 위 선실 배지도 짧게 누르면 같은 상세 창을 연다. 비우기는 상세 창의 '내리기'로 옮겨, 실수로 누르기만 해도 빠지던 문제를 없앤다.

### 2. 왼쪽: 배 위 선실 배치 (새 `app/lib/crew/crew_ship.dart`)
- `CrewShip` 위젯을 만든다.
  - `myBlueprint` 로 내 배 설계도를 얻는다.
  - `LayoutBuilder` 에서 `BlueprintPreview` 와 같은 식으로 `cell` 을 정한다.
  - `ShipGridView(bare: true)` 위에 `Stack` 으로 선실마다 `Positioned` 배지를 겹친다.
- 칸 좌표 식은 `ShipGridView.cellRect(h, cell, x, y)` 정적 함수로 꺼내 두 곳이 같이 쓴다(중복 제거).
- **배지**
  - 크기는 `max(cell * 1.4, 44)` 정사각이고, 선실 칸 가운데에 둔다. 손가락 터치 영역 44px 이상을 지킨다.
  - 찬 선실: 해적 얼굴(`RarityCard` 축소판, 등급 테두리)과 왼쪽 위 번호.
  - 빈 선실: 점선 원과 번호.
  - 배지마다 `DragTarget<String>` 이다. 지금 `CabinSlot` 의 `_fits`·`_place` 규칙을 그대로 쓴다: 놓으면 배치하고, 이미 있던 해적과는 자리를 바꾸고, 코스트를 넘으면 붉은 테.
  - 찬 배지는 `Draggable`(즉시 끌기)이라 다른 선실로 끌어 자리를 바꾼다. 누르면 상세 창이 열리고, 내리기는 그 안에서 한다(마지막 1명은 못 뺀다).
- **배지 아래 이름:** 셀이 작아 이름표를 붙이면 겹친다. 그래서 배 그림 아래에 '1 문어 · 2 거북' 같은 한 줄 범례를 둔다. 글자는 l10n 이름 키를 쓰고, 번호와 이름만이라 새 문자열은 거의 없다.
- `crew_screen.dart` 왼쪽 패널
  - 슬롯 줄을 `CrewShip` 으로 바꾼다.
  - 폭은 화면의 약 45%(최소 330)로 넓혀 배가 충분히 크게 보이게 한다.
  - 그 아래 `CostBar`·`DeckEvalView` 는 그대로 둔다.
- `CabinSlot` 은 쓰는 곳이 없어지면 지운다. 줄 수가 줄어든다.

### 3. 오른쪽: 필터 (새 `app/lib/crew/crew_filter.dart`)
- `CrewFilter` 값 객체: `Set<Rarity> rarities`, `Set<PirateFamily> families`, `Set<AmmoType> ammos`.
  - 비어 있으면 '전체'다. 같은 묶음 안은 OR, 묶음끼리는 AND 다.
  - 순수 함수 `bool matches(PirateDef def, PirateSpec spec)` 로 둔다. 테스트하기 쉽다.
- 목록 위에 필터 막대를 둔다.
  - 등급·계열·탄종 세 버튼. 누르면 아래로 칩 선택판(`Wrap` 의 `FilterChip`)이 펼쳐지고, 고른 개수는 버튼에 배지로 보인다.
  - 오른쪽에 '초기화'와 'n / m명'.
  - 칩 글자는 이미 있는 등급·계열·탄종 이름 키를 쓴다. 새 키는 필터 막대 제목, 초기화, 'n / m명', 결과 없음 안내뿐이고 ko·en 을 같은 커밋에 넣는다.
- 필터 상태는 화면 상태로만 둔다(나갔다 오면 초기화). 결과가 0명이면 '조건에 맞는 해적이 없습니다'와 초기화 버튼.
- 레벨 필터·정렬은 넣지 않는다. 계획서 R4 에 적는다.

### 4. 줄 수·구조
- `crew_screen.dart`(174)·`crew_widgets.dart`(266)는 300줄 안에 둔다. 새 위젯은 새 파일로 나눈다.

## 테스트 (한국어 이름)
- `crew_filter_test.dart`(순수)
  - 등급 하나 → 그 등급만 남는다.
  - 등급+탄종 → 둘 다 맞는 해적만 남는다.
  - 비우면 전부다.
  - 같은 묶음 둘을 고르면 합집합이다.
- 위젯 테스트 (`screens_test` 고침 / 새 `a62_crew_test`)
  - 목록을 세로로 밀면 덱이 바뀌지 않고 스크롤만 된다. 옛 `Draggable` 에서는 실패하는 것을 확인한다.
  - 길게 눌러 끌어 선실 배지 3에 놓으면 덱 3번이 된다. 기존 `dragFrom` 테스트를 `longPress` 끌기로 바꾼다.
  - 목록 카드를 누르면 상세 창이 뜨고 이름·설명·탄종이 보인다. 덱은 바뀌지 않는다.
  - 상세 창 '태우기' → 빈 선실에 탄다. 출전 해적의 '내리기' → 빠진다. 마지막 1명은 내리기가 꺼진다.
  - 선실 배지 1을 배지 2로 끌면 자리가 바뀐다.
  - 배 위 배지 수 = 선실 수(`hull.cabinSlots`)이고, 배지 i 의 위치가 `blueprint.cabins[i]` 칸 위다.
  - 필터 막대에서 '전설'을 고르면 목록에 전설만 남고, 개수 글자가 바뀐다.
- `a9_screens_test`·`dev_practice_test` 의 GridView 항목 수 검사는 필터를 끈 상태 기준으로 맞춘다.
- 골든 `crew_{ko,en}_{high,low}.png` 를 다시 만든다. `screens_test` ko/en 넘침 검사를 통과해야 한다.

## 진행 순서
1. 다른 세션에 알리고 브랜치 ref 를 만든다. 계획 파일을 옮기고 README 색인에 넣는다.
2. 설계서 §13.7 문장 → `/doc-sync`(계획서 A62·R4 항목·해시) → ADR-109.
3. 1(잡힘 고침) → 3(필터) → 2(배 위 배치) 순서로 구현한다. 작고 확실한 것부터 한다.
4. 깨끗한 복사본에서 verify → rules-reviewer → 커밋 → 브랜치 push → main 병합(commit-tree) → main push.
5. 사람 확인(실기기)을 보고에 적는다: 길게 누르기 200ms 가 답답하지 않은지, 배지 크기, 작은 화면에서 배 크기.
