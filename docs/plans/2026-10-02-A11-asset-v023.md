# 에셋 v0.23 수용 + A11 마무리

## Context
디자인 쪽이 두 번 보고했다. v0.22(23~28단계)는 이미 처리했다(ADR-058, A11 머지 `3c9d821`). 이번에 할 일은 v0.23(29~37단계)이다. 설계서에는 있는데 그림이 없던 것들이다: 해역 배경, 메타 아이콘 85개, 선형·모듈·특수 블록, HUD 7상태, 캠페인·조선소·상점 등 화면 시안, 보스 12식, 컷신.

원본은 `art/pb_v0.23_main/` 에 합쳐 두었다(v0.22 + update + screens_v2, 파일 5,755개, 덮어쓴 파일 없음, git 제외).

대조 결과는 다음과 같다.
- **설계서와 같은 것:** 해역 6개와 이름(§5.4·§15.3), 보스 12식 이름(§5.4), 모듈 9종(§3.3), 선형 격자·선실 수(§3.1), AI 성격 4·티어 6·재화·궤적 모양 7·바다의 심장 6조각, 세트 10개.
- **데이터로 쓰면 안 되는 것:**
  - `ship/hulls/hulls.json` 격자는 블록을 꽉 채워서 건조 포인트(BALANCE A3.1)의 약 2배다. 추천 설계도도 프리깃 기준인데 앱·설계서 MVP 는 슬루프 기준이다.
  - `boss/bosses.json` 선원 목록은 같은 해적이 중복되고, 중간 보스와 해역 보스의 목록이 같다(자리 표시).
- **근거 없는 값:** 크라켄 촉수 6개와 체력 칸 4/3/2/1. 사용자 결정: 계획서 11장 미정 사항에 R3 로 남긴다.
- **A11 의 마지막 미정 항목이 풀렸다.** v0.23 README 는 "흘수선 아래 참나무·소나무 칸은 `bot`(젖은) 타일"이라고 한다. 지금 앱은 `bot` 을 용골 줄(y==0)에 재질과 무관하게 쓴다(`app/lib/game/sprites.dart:54`, `ship_view.dart:108·243`).

사용자 결정은 세 가지다.
- 디자이너 제안 4개를 모두 설계서·BALANCE 에 넣는다.
- 크라켄·보스 선원 문제는 미정 사항(R3)에 남긴다.
- 범위는 문서 + A11 마무리. v0.23 을 이미 끝난 화면에 적용하는 일은 새 A12 로 계획서에만 넣는다.

## 4. A11 마무리 코드 (젖은 타일, 설계서 §10.2)
- `app/lib/game/sprites.dart`: `tile(m, x, y, {bool wet = false})`. 참나무·소나무이고 `wet` 이면 `bot_<v>`, 아니면 재질 타일이다. `keel` 인자는 없앤다. 젖음 판정은 순수 static 함수로 만든다: `isWet(y, draft) => y * cellUnit + cellUnit ~/ 2 <= draft`. `match_state.dart:95` 의 선실 잠김 판정과 같은 식이다. 렌더 전용이고 `_state.draft` 는 시뮬 상태라 리플레이에서도 같다.
- `app/lib/game/view/ship_view.dart:104·243`: `keel: y == 0` → `wet: BattleSprites.isWet(y, _state.draft)`. 침수로 배가 내려앉으면 젖은 줄도 늘어난다.
- `app/test/cabin_render_test.dart:84` 를 고치고, 테스트를 한국어 이름으로 추가한다:
  - 흘수선 아래 참나무·소나무는 젖은 타일, 철판·코르크·망사는 그대로
  - 잠김 경계 칸 가운데
  - 침수로 draft 가 늘면 젖은 줄이 는다
- 계획서 A11 타일 항목을 [x] 로 바꾼다.
