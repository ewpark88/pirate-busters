# 계획: 탄 비행 시간을 늘리고, 카메라가 착탄까지 탄을 따라가게 기재

## Context

사용자: 폭탄을 쏘고 떨어지는 속도가 너무 빠르다. 쏘는 속도를 늦추는 규칙·수치를 설계서와 BALANCE.md 에 적고, 탄이 적 배에 도착할 때까지 카메라가 따라가도록 기재한다.

현재 상태(코드·문서):
- 중력 `gravityPerTick` = 36칸/초² (`packages/pb_sim/lib/src/world/world.dart`, ADR-010 임시값). 사거리 등급의 탄속은 √(사거리 × 중력)으로 이 값에서 계산된다(§2.8). 최대 힘·45° 기준 비행 시간 = 1.414 × √(사거리 ÷ 중력):

| 등급 | 사거리 | 지금(중력 36) | 제안(중력 16) |
| --- | --- | --- | --- |
| 짧음 | 22칸 | 1.1초 | 1.7초 |
| 보통 | 36칸 | 1.4초 | 2.1초 |
| 긺 | 50칸 | 1.7초 | 2.5초 |
| 매우 긺 | 66칸 | 1.9초 | 2.9초 |

- 사거리를 그대로 두고 중력과 탄속을 함께 낮추면 비행 시간만 √(36/16) = 1.5배 길어진다. 바람 가속(`windAccel`, 단계당 1/1000칸/틱²)은 중력에 비해 상대적으로 세지므로 중력에 대한 비율로 다시 정의해야 한다(지금 3단계 = 중력의 7.5%).
- 카메라: 설계서 §2.1 은 “발사하면 탄과 목표가 한 화면에 들어오도록 줌아웃하며 따라가고, 착탄 뒤 내 배로 돌아온다”고만 적혀 있고, 앱 `camera_director.dart` 는 줌아웃 + 지수 추적(followRate 4)이다. “탄을 놓치지 않고 착탄까지 따라간다”가 규칙으로 명시돼 있지 않다.
- M3(탄도)·M4(카메라)는 끝난 단계이므로 코드 반영은 규칙 11 에 따라 계획서 12장 끝에 **A6** 단계로 붙인다.

## 설계서 수정 (규칙만, 수치 없음)

- **§2.8 사거리**에 불릿 추가: “**비행 시간:** 사거리는 유지하고 중력과 탄속을 함께 낮춰, 탄이 날아가 떨어지는 모습이 보이게 한다. 긴 사거리를 최대 힘으로 쏘면 몇 초 동안 날아간다(중력·등급별 비행 시간: BALANCE.md A2.8). 바람 가속은 중력에 대한 비율로 정한다(A2.3). 탄이 나는 동안 턴 타이머는 멈추므로(2.3) 턴 시간에는 영향이 없다.”
- **§2.1 카메라** 불릿을 바꿈: “발사하면 카메라가 탄을 따라 이동하며 탄이 화면 밖으로 나가지 않게 하고, 탄과 목표가 함께 보이도록 필요한 만큼만 줌아웃한다. 탄이 적 배에 닿아 착탄·파괴 연출이 끝날 때까지 따라간 뒤 내 배로 돌아온다. 상대 턴 재생도 같다. 분열·다중투하처럼 탄이 여럿이면 앞선 탄을 따른다.”
- **§2.3 바람** 행에 “세기는 중력에 대한 비율로 정한다(A2.3)” 한 마디.

## BALANCE.md 수정

- **A2.8** 끝에 “**탄도 시간**” 표: 중력 16칸/초²(이전 36, ADR-010 임시 → 이번 임시값), 등급별 최대 힘·45° 비행 시간(위 표의 제안 열), 목표 “긴 사거리 2.5초 안팎”, Remote Config `range_gravity`.
- **A2.3** 바람 행에 “가속 = 단계당 중력의 2.5% (3단계 = 7.5%)”.
- B부는 비행 시간을 쓰지 않으므로 그대로.

## 계획서 수정

- **12장 A6 “탄 비행 시간·카메라 추적” 단계** 추가(선행 A5):
  - [ ] `pb_sim` 중력 상수를 A2.8 값으로 바꾸고, 사거리 등급 탄속 표를 √(사거리 × 중력)으로 다시 계산한다 (§2.8)
  - [ ] 바람 가속을 중력의 비율로 정의하고 정수 해상도를 맞춘다(단계당 중력의 2.5%가 정수로 표현되게 단위를 올린다) (§2.3, A2.3)
  - [ ] 테스트: 등급별 최대 힘·45° 비행 틱 수가 A2.8 표(±1틱)와 같다. 골든 리플레이·해시 재생성
  - [ ] 앱 카메라: 발사부터 착탄·파괴 연출 끝까지 탄을 따라가고 탄이 화면 밖으로 나가지 않는다. 여러 탄이면 앞선 탄. 상대 턴 재생도 같다 (§2.1)
  - [ ] AI 조준 솔버(M6)는 시뮬레이션 상수를 그대로 쓰므로 재계산만 확인
  - 완료 조건: 실기기에서 긴 사거리 최대 힘이 A2.8 시간만큼 날고 카메라가 착탄까지 따라간다. verify 통과.
- 11장 미정 사항에는 넣지 않는다(값이 정해졌으므로).
- 머리 해시 갱신.

## ADR

`docs/DECISIONS.md` 끝에 ADR-043(번호는 실행 때 확인) “탄 비행 시간 1.5배(중력 36 → 16)와 카메라 착탄 추적”: 배경(실기기 체감), 결정(사거리 유지·중력·탄속 동시 하향, 바람은 중력 비율, 카메라 규칙 명시, 코드는 A6), 대안(탄속만 낮추기 — 사거리가 줄어 A2.8 표 전체가 흔들림 / 재생 속도만 늦추기 — 판정과 연출이 어긋남), 영향.

## 실행 순서

1. 설계서 §2.1·§2.3·§2.8 문장 치환(앵커 count == 1).
2. BALANCE.md A2.3·A2.8 표 추가.
3. 계획서 A6 추가, `dart run tool/check_doc_sync.dart` 로 새 해시 → 머리 갱신 → 통과 확인.
4. ADR 추가. 다른 세션(pirate-aiming-redesign, A5 코드 작업 중)에 A6 추가와 해시 변경을 알린다.
5. 커밋은 사용자가 요청할 때.
