# 설계서 아트 동기화 (`/art-doc-sync`, 사용자 승인 작업)

## Context

아트 에셋 v0.21 과 ‘해적 캐릭터 단계별 개선’ 22단계 디자인이 설계서 §10·§13·§4.3 문구보다 앞서 있다. 사용자가 승인한 8개 항목만 설계서에 반영하고(수치 변경 없음, BALANCE.md 는 건드리지 않음), `/doc-sync` 절차로 계획서를 맞춘 뒤 ADR 을 남긴다. 코드 변경은 없다 — 아직 구현되지 않은 것은 계획서 12장 끝에 새 추가 단계로만 넣는다.

조사 결과: 8개 항목 중 설계서에 이미 반영된 것은 없다. 설계서 안에서 `10.3` 을 참조하는 곳은 제목뿐이라 10.4·10.5 를 뒤에 붙여도 깨지는 참조가 없다.

## 시작 조건 (사용자 결정: A10 이 끝난 뒤 같은 폴더에서)

- 다른 세션(zigzag-crack-damage-system)이 이 폴더를 `feat/A10-crack-damage` 로 두고 A10 을 구현 중이다. **A10 이 커밋·머지될 때까지 설계서·계획서를 고치지 않는다.**
- 승인 직후 그 세션에 알린다: 이 세션은 A10 이 끝난 뒤 `docs/art-sync` 에서 설계서 §4.3·§10·§13.4·§13.9·§14.4, 계획서(문구·새 추가 단계·해시), DECISIONS 를 고칠 예정이니 A10 머지가 끝나면 알려 달라고 한다.
- 완료 신호(그 세션의 메시지 또는 사용자 알림)를 받으면: `git status` 깨끗함·실행 중인 dart 프로세스 없음을 확인 → 최신 `main` 에서 `docs/art-sync` 브랜치 생성·전환(전환 전에 다른 세션에 알림).
- A10 사이에 설계서·계획서가 또 바뀌었을 수 있으므로 대상 절(§4.1, §4.3, §4.8, §10, §13.4, §13.9, §14.4)을 다시 읽고 시작한다. ADR·추가 단계 번호는 그때의 다음 번호를 쓴다(지금 기준 ADR-053, A11).

## 설계서 수정 — 하나씩 순서대로 (`Pirate Busters 게임 설계서.md`)

명령 파일(`.claude/commands/art-doc-sync.md`)의 문안을 그대로 쓴다. 항목마다 따로 고치고 한 줄씩 보고한다.

| 순서 | 절 | 바꾸는 것 |
|---|---|---|
| 1 | §10 머리말 | “스타일 규칙: 외곽선은 진갈색 … 볼터치로 단순하게.” 문장을 톤·외곽선(#14161c)·빛(주황 림라이트 #ffb36b)·얼굴·장비·팀 색 목록으로 교체. 첫 문장과 마지막 문장은 유지 |
| 2 | §10.1 | 표 ‘무기·투사체’ 행 교체(발사체 35 + 소형 폭탄 1 + 효과 아이콘 10), ‘탄종 아이콘 13’ 행 추가, “게임 크기(약 80px)” → “키 약 1.5칸 …”, 애니메이션 상태 목록 앞에 부위 리그·전투 외곽선·고유 무기 3항목 추가 |
| 3 | §10.2 | 첫 문장만 SVG 타일(무늬 4가지, 칸 번호 고정)·젖은 타일·선실 타일 문장으로 교체. ADR-052 로 들어간 금·찢긴 가장자리 문장은 그대로 |
| 4 | §10.4 (새) | 10.3 사운드 **뒤에** ‘전투 연출’ 절 추가 |
| 5 | §10.5 (새) | 10.4 뒤에 ‘등급 표현’ 절(카드 프레임 표, 전투 등급 연출 표) 추가 |
| 6 | §4.3 | 예시 `render.species` `"urchin"` → `"uni"`, species = 아트 에셋 키 설명 문장, 계열 키·탄종 키·해적 40명 id/species 표, 랍 `lobster` 문장 추가 |
| 7 | §13.4·§13.9 | 해적 카드에 “등급 프레임(10.5)을 따른다”, 카드 한 장의 “등급 색 테두리” → 등급 프레임 + 탄종 칩, 상세 왼쪽에 고유 무기·등급 연출 문장 |

대조 확인(이미 함): 앱 데이터의 12명 species(octo·uni·pang·hippo·sword·otter·puffer·polly·gull·pelly·shark·turtle), 계열·탄종 키, `anims.json` 캔버스 240×324·기준점 (120, 315), 무기 PNG 35 + bomblet + 효과 아이콘 10, 탄종 아이콘 13 이 명령 문안과 맞는다.

## 계획서 반영 (`Pirate Busters 개발 계획서.md`, `/doc-sync`)

**기존 문구를 설계서에 맞춤** (체크 상태는 그대로)
- M4 블록 렌더(§10.2): “재질별 타일 하나 … 코드로” → SVG 타일 + 손상 단계 겹쳐 그리기. 못 한 부분은 새 추가 단계로 넘긴다고 적는다
- M4 해적 렌더(§10, §10.1): 옛 스타일 규칙(진갈색·푸른 빛·볼터치)·“약 80px” 를 §10 머리말 참조와 “키 약 1.5칸” 으로
- M4 글꼴(§14.4): 예시 글꼴 목록, 지금은 Jua 만이고 나머지는 새 추가 단계
- M5 해적 데이터(§4.3)·해적 카드(§13.4): `species` 는 아트 에셋 키, 카드 모양은 등급 프레임(새 추가 단계)
- R6 아트 완성·9장 운영(§10.1): “무기·투사체 약 15” → 고유 무기·탄종 아이콘 수량, 시즌 해적은 고유 무기 1개·신화 프레임(§10.5)
- A2 해적보감(§13.9): 카드는 등급 프레임·탄종 칩, 상세 공격 동작에 고유 무기·등급 연출

**새 추가 단계 A11 (12장 끝, 절대 규칙 11)** — 조사에서 ‘없음·일부’로 나온 것만 미체크 항목으로 넣는다
- 글꼴: Black Han Sans·IBM Plex Sans KR(OFL) 추가와 적용, 골든 재생성 (§14.4) — 지금 `app/assets/fonts` 에는 Jua 뿐
- 카드 등급 프레임: `ui/cards/*` 세 겹 공용 위젯, HUD 카드·선원 카드에 적용 (§10.5, §13.4) — 에셋은 있고 쓰는 코드가 없다(`pirate_cards.dart`, `crew_widgets.dart`)
- 전투 등급 연출: `anims.json` `rarityFx`(발밑 고리·외곽 빛·점선 색·꼬리·명중 고리·흔들림 배율) (§10.5)
- 고유 무기 꼬리(`weapons.json` `trail`)와 명중 이름표 (§10.1) — 무기 그림 자체는 이미 쓴다(`weapon_styles.dart`)
- 전투 연출(§10.4): 히트스톱, 계열별 명중(`anims.json` `impacts`), 붕괴 기울어 떨어짐·물보라(`fx/collapse/*`), 펀치 줌·배 흔들림, 피해 숫자 튐·이름표, 조준 고무줄·각도 호·힘 링·점선 흐려짐, 남은 턴 배지, 강습·지원·설치 전달 연출
- 타일(§10.2): 무늬 4번째(`sprites.dart` 는 3가지만 씀), 선실 타일(`ship/rooms/*`, `room_wall_*` 미사용), 젖은 타일·철판 무늬(에셋 없음 → 에셋 필요로 표시)
- 에셋 키: 랍 `lobster`(지금 폴더는 `lob`) 맞춤, `pb_data` 스키마 검사에 species 키 확인
- 선행: A10(같은 `ship_view.dart`), 새 글자는 ko·en ARB

**머리:** `기준 문서 동기화` 해시·날짜 갱신(`dart run tool/check_doc_sync.dart` 가 알려 주는 값).

## ADR (`docs/DECISIONS.md`)

`/adr 설계서 아트·등급 표현·에셋 키 동기화` — 다음 번호로, 기존 형식(배경 → 결정 → 대안 → 영향). 설계서를 사용자 승인으로 에이전트가 직접 고쳤다는 것(ADR-025·051·052 선례), 수치 변경 없음, 구현은 A11 로 넘김을 적는다.

## 검증

- `dart run tool/check_doc_sync.dart` 통과
- `bash tool/verify.sh` 통과 (명령 9-5 가 요구)
- 설계서에서 `10.1`~`10.5`·`13.4`·`13.9` 참조가 모두 실제 절을 가리키는지 grep 으로 확인
- 설계서 `git diff` 가 승인된 절(§4.3, §10, §10.1, §10.2, §10.4, §10.5, §13.4, §13.9, §14.4) 밖을 건드리지 않았는지 확인

## 마무리 보고

- 고친 절과 전·후 요지 표, 끝난 단계에 미치는 영향 표(절 / 단계 / 코드 수정 필요 여부)
- 커밋은 사용자가 요청할 때만: 설계서·계획서·DECISIONS 를 한 커밋으로, 파일을 골라 `git add`. 추적 안 된 `.claude/commands/art-doc-sync.md` 를 같이 넣을지는 그때 묻는다

## 고치지 않고 제안으로만 남길 것 (지금까지 찾은 것)

- §6.5 출석판 “뽑기 칸은 등급 색 테두리”, §13.9 목록 그림 안의 “← 등급 색 테두리” 주석 — 승인 목록 밖
- §4.3 문안의 `weapons/<species>.svg` 는 아트 패키지 원본 기준이고 앱은 PNG 를 쓴다
- 탄종 아이콘 5개의 파일 이름이 탄종 키와 다르다(explode·rapid·snipe·plant·multidrop, 코드에서 대응 중)
- `docs/ASSETS.md` 가 말하는 `art/pb_v0.21_main/` 이 없고 실제 폴더는 `art/pb_assets_v0.15`(내용은 v0.21)
